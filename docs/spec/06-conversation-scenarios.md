# 06 對答情境

> 版本：v1.2（POC）・2026-10-30（第 1 節補需求 3-2 三類問答的對應；第 7 節新增 W12 輸入框、W13 小螢幕；v1.1 2026-10-29 依七個問題分類、本顧客註記規則、員工帳號與 `certNo` 重寫，設計見 [customer360 內容重寫設計](../superpowers/specs/2026-10-28-customer360-content-rewrite-design.md) v0.2）

## 1. 設計思路

小幫手只出現在**個人 360 頁面**，使用者是「已經打開某位顧客，想快速掌握經營重點」的理專、AO 和主管。情境依這個時刻的需求設計：

| 時刻           | 使用者想知道                           | 對應的問題分類 |
| -------------- | -------------------------------------- | -------------- |
| 剛打開頁面     | 這是什麼樣的顧客？有什麼註記？         | 顧客概況       |
| 看資產與負債   | 資產配置、負債結構、和客群比起來如何？ | 資產負債       |
| 看會員等級     | 離升等還差多少？有沒有降等風險？       | 會員等級       |
| 規劃經營方向   | 對哪些商品有興趣？系統推薦什麼？       | 商品機會       |
| 了解往來與通路 | 本行是不是主要往來？用什麼管道聯繫？   | 往來與通路     |
| 準備聯繫       | 有哪些提醒要處理？有什麼活動可以搭配？ | 聯繫準備       |
| 顧客問起市場   | 今天大盤、某檔股票怎麼樣？             | 市場快訊       |

問題分類就是 Prompt 管理中的 System Instructions（見 [07-prompt-examples.md](07-prompt-examples.md)），每個分類的範例問題會顯示為對話視窗的快捷按鈕；按鈕與管理頁清單依 `configKey` 排序（資產負債、聯繫準備、顧客概況、往來與通路、市場快訊、會員等級、商品機會）。

與需求 3-2 的對應：

| 需求 3-2 | 對應的問題分類 | 說明 |
| --- | --- | --- |
| 1. 顧客概況 | 顧客概況 | 基本資料（去識別化）、會員等級、畫像標籤與註記 |
| 2. 經營機會 | 商品機會（另有資產負債、會員等級、往來與通路） | 依平台 API 回傳的意圖、財富潛力、系統推薦與洞見整理關注面向 |
| 3. 互動摘要 | 聯繫準備 | 以即時提醒（關鍵提醒、註記）與專屬活動協助準備後續聯繫。平台的互動紀錄在個人 360 的下一層頁面，需進入該頁並通過該頁的權限審核才能看到細節，不在 360 頁的 API 內，小幫手不繞過這層審核；被問到時引導至互動紀錄頁（O1），互動紀錄工具待平台提供該頁 API 與權限規則後再加（見 [01-architecture.md](01-architecture.md) 9.3） |
| 4. 其他 | 不屬於分類的題目（Q9 電話開場白）、市場快訊 | 站在「正要打電話給顧客」的使用者角度設計 |

所有情境共同遵守：

- 對話只針對頁面上的這位顧客，回答以「本顧客」稱呼。
- LLM 看不到顧客編號（`certNo`，即身分證字號）、姓名或任何識別資料。
- 小幫手唯讀，只查詢和整理。
- 小幫手看不到互動紀錄、交易明細、個別持有商品與經辦人員姓名；被問到時說明無法提供並引導至平台對應頁面。
- **本顧客註記規則**（程式在組 prompt 時注入「本顧客註記」，只在 `FULL`）：
    - 不宜行銷：不產出商品機會、推薦產品與行銷話術；回答開頭說明「本顧客有不宜行銷註記」，改從關懷與服務方向回答。
    - 客訴、特殊客群、應注意名單：照常回答，但在結論前先列「注意事項」，說明註記類別並提醒依規定程序處理（例如特殊客群需確認商品適合度）。
    - 只說明註記的類別與到期日，不推測原因。
- 商品規則：可轉述系統推薦產品、經營洞見與意圖最強的商品類型並說明根據；不自行推薦具體商品或個股，不提買賣時點，不保證報酬。
- 每個回答都標示資料日期（`yyyy/MM/dd`）；數字照工具回傳的寫法，不自行換算或相減。

每個情境都標示預期使用的工具，作為工具選擇正確率的驗收依據；其中 34 題已轉成 Prompt 評測集的題目（見 1.3），可由 Prompt 管理頁自動執行。

### 1.1 驗收欄位說明

- **帳號 / 頁面**：用哪個模擬帳號登入、在哪位顧客的 360 頁面（帳號見 [02-rest-api.md](02-rest-api.md) 1.2，顧客見 [03-tool-catalog.md](03-tool-catalog.md) 5.2）。
- **預期工具**：模型應該呼叫的工具；標「不應出現」的工具出現了就算失敗。
- **必要內容 / 禁止內容**：回答中必須出現 / 不得出現的資訊。
- **檢查點**：回應的 `blocks`、`citations`、`disclaimer`、`toolCalls`，以及**送進 LLM 的內容**（以單元測試或 debug log 驗證，不含識別資料）。
- **引用**：有工具依據的區塊（不含標題）應帶 `citations`，且每個編號都能在 `citations[]` 找到；每次成功的工具呼叫都有一筆 `citations`（沒被引用的 `cited` 為 `false`）。顧客工具的引用標題為「個人360・」加實際回傳的區塊名稱（例如「個人360・資產負債、會員等級」），`description` 為「資料日期 yyyy/MM/dd」；沒有工具依據的內容（例如建議話術）不必有引用。各情境的檢查點只列出該情境特有的引用內容。

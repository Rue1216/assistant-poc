# Demo 檢查清單

> 依 [06-conversation-scenarios.md](spec/06-conversation-scenarios.md) 第 9 節的 demo 腳本。每一步做完勾選，並在「實際結果」填寫觀察到的情況；不符合預期時記下差異，不要臨時改程式。

## 事前準備

- [ ] 重設資料：`docker compose down -v` → `docker compose up -d`（見 [setup.md](setup.md) 7.1）
- [ ] 依 [setup.md](setup.md) 第 7 節啟動後端與前端；後端 log 有 `seed completed: 6 configs published`
- [ ] 準備兩個瀏覽器視窗：一般視窗與無痕視窗（步驟 13 需要兩個不同的登入 session）
- [ ] 換帳號時，先按右上角登出再登入
- [ ] 決定用淺色或深色模式展示（右上角月亮／太陽按鈕，選擇會記住）

> 個人 360 頁面除了顧客名片，其他提醒與圖表都是寫死的示意資料（每位顧客都一樣，頂部列有標示），數字和小幫手的回答對不上是正常的；被問到時說明 360 頁是平台既有頁面的替身。

> 步驟 11 設定的預約要在步驟 15 回來看結果，中間至少隔 2 分鐘。
> 步驟 19、20 的評測會呼叫 GPT（實測每次約 16 萬 token、約 2 分鐘），後端需要有真實的 `OPENAI_API_KEY`；同時只能有一個評測，步驟 19 結束後再做步驟 20。步驟 19、20 的後端行為已於 2026-10-27 以 API 實測（見設計規格 11.4）；畫面部分與步驟 17、18 待實測。
> 步驟 2、3、17–20 現在帶有路由檢查，尚未重新實測（留待實機驗證時重測），所以這些步驟的「實際結果」記錄早於路由功能。

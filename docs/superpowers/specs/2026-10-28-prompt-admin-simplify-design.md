- 版本：v0.5
- 狀態：已實作

## 1. 目標與範圍

### 1.1 目標

1. 使用者（後台管理人員、IT 管理人員，使用頻率低）第一次打開就能完成兩條主要流程：「修改 → 評測 → 發布」與「找回舊版本」。
2. 畫面上每個元素都要通過「少了它使用者會卡住嗎？」的檢查；做決定需要的資訊放第一層，診斷細節點開才看到。
3. 同一件事只出現一次（不再有兩顆「建立草稿」、多種「返回」）。
4. 發布前檢查只擋程式真正依賴或會造成外洩的內容，不用手動觸發。

## 2. 頁面骨架與設定選單

```
  Prompt 管理                                         [＋ 新增問題分類]
  管理小幫手的 System Prompt 與問題分類，發布後立即套用於所有對話。
┌────────────────────────────────────────────────────────────────────┐
│ [主要系統提示 ▾]  [草稿]                                            │
│ system.main・目前生效：10/24 19:31（system 發布）                   │
│ ─ 內容 ─ 版本 ─ 評測 ▲ ──────────────────────────────────────────── │
│  （分頁內容，見 3–5 節）                                            │
└────────────────────────────────────────────────────────────────────┘

設定選單展開：
┌──────────────────────────────┐
│ [搜尋名稱或 key            ] │
│ System Prompt                │
│ ▌主要系統提示         [草稿] │
│ 問題分類 5                   │
│  聯繫準備                    │
│  顧客概況 [已排程 10/24 09:00]│
│  …                           │
└──────────────────────────────┘
```

- 沒有左側清單；主卡片全寬。
- RWD 只有單欄：1100px 以下頁首改為上下排、版本分頁的列表移到檢視區上方（同現況規則）；設定選單面板在窄螢幕時與卡片同寬。

### 2.1 設定選單（`ConfigPicker`）

- 收合時是一顆按鈕：目前設定的名稱（標題字級）＋「▾」，位置在標題列最左，取代原本的名稱文字。
- 展開後的面板（最高 60vh，超過可捲動）：
    - 搜尋框：展開時自動聚焦；比對名稱或 key，不分大小寫。
    - 兩個分組：「System Prompt」「問題分類 {N}」（N 為問題分類總數）。畫面上一律稱「問題分類」，不再混用 System Instructions。
    - 每項只有**名稱與一個狀態標籤**：草稿、已排程 {MM/DD HH:mm}；沒有編輯中版本時不顯示標籤。目前的設定以左側綠條標示（同原清單選取樣式）。
    - 某組沒有符合項目時整組隱藏；兩組都沒有時顯示「沒有符合的設定」。
- 鍵盤：按鈕上 Enter／Space／↓ 展開；搜尋框內 ↑↓ 移動目前項目（`aria-activedescendant`），Enter 選取；Esc 關閉並把焦點還給按鈕；Tab 或點面板外關閉。
- 選取走既有的換設定流程：有未儲存的修改時先問「放棄尚未儲存的修改？」，按取消則維持原設定與原分頁。
- 移除：左側清單元件（`ConfigList`）、key、作者、發布時間、版本歷程。

### 2.2 標題區

- 第一行：設定選單（名稱）＋狀態標籤（草稿／預約 {時間} 發布／目前生效）。
- 第二行 meta：`{configKey}`・目前生效：{published.updatedAt}（{published.updatedBy} 發布）；從未發布時為「尚未發布」。
- 移除「最後儲存：誰・何時」（版本分頁的草稿列可見）。

### 2.3 分頁

- 「內容」「版本」「評測」。評測分頁標題旁顯示最近結論符號（▲ 變好、▼ 有指標變差、≈ 差不多），只在「已評測且之後未修改」時顯示；本設定的評測執行中顯示「…」（他人評測別的設定時不顯示）。
- 切換設定 → 回到「內容」。
- 切換分頁**不遺失未儲存的修改**（表單在 `usePromptAdmin` state）；「放棄尚未儲存的修改？」只在換設定、離開頁面、建立新問題分類、以舊版本建立草稿時出現（同現況）。
- 移除所有「← 返回編輯」「返回目前生效的版本」按鈕與「正在檢視…」唯讀橫幅。

### 2.4 頁首與權限

- 說明文字縮為一句（見 2 節示意）；「＋ 新增問題分類」固定在頁首（沒有頁籤可依附），顯示條件與權限同現況；建立成功後選到新的問題分類。
- 沒有 `AI_CONFIG_EDIT` 的人可看三個分頁，看不到編輯、發布、建立草稿、執行評測（同現況）。

## 3. 內容分頁

### 3.1 有編輯中版本

由上而下：

1. **提示列**（只有 System Prompt）：「這份會和 {N} 份已發布的問題分類一起送給模型，影響所有對話。查看問題分類 →」。取代藍色資訊橫幅與「送給模型的系統訊息」兩步驟圖；點連結展開設定選單（2.1）。問題分類沒有提示列。
2. **名稱／修改說明**：同一列。修改說明的「（選填，最多 200 字）」改為 placeholder「選填，例如：補充無權限時的回覆方式」，上限不變。
3. **編輯器**：「編輯／預覽」分頁與「{size} / 64 KB」不變。
    - 必要章節：依 6 節，只有問題分類要求 `## 適用問題`。**只在缺少時**於編輯器標題列顯示「缺少「## 適用問題」」；齊全時、以及 System Prompt 一律不顯示。
    - 預覽：保留與目前生效版本不同的綠底標示；問題分類保留快捷按鈕預覽。
4. **衝突橫幅**（409）：保留，位置在分頁最上方。
5. **底部動作列**（sticky）：左側發布前檢查、右側按鈕。

#### 發布前檢查（動作列左側，一行）

自動執行，沒有「檢查」按鈕。檢查的是**已儲存**的編輯中版本（既有 `POST .../draft/validate`，不先儲存）。

觸發時機：

- 載入有編輯中版本的設定（選取設定、重新載入、建立草稿、以舊版本建立草稿後）。
- 每次儲存成功後（含「儲存並評測」、取消排程）。
- 發布失敗回 422 時，直接以回應的錯誤顯示為未通過（同現況，不另呼叫）。

| 狀態           | 顯示                                                |
| -------------- | --------------------------------------------------- |
| 檢查中         | 「檢查中…」                                         |
| 通過           | 「✓ 發布前檢查通過 ▸」，點開列出通過的規則          |
| 未通過         | 「✕ {n} 項未通過」，自動展開列出原因                |
| 有未儲存的修改 | 保留上一次結果，後面加小字「・儲存後重新檢查」      |
| 檢查呼叫失敗   | 不顯示結果（錯誤由 apiClient Toast）                |

- 檢查回應抵達時已換到別的設定 → 丟棄（同現有 `onKey` 作法）；連續觸發只採用最後一次的回應。
- 自動檢查不占用 `busy`，不會讓儲存、發布按鈕停用。
- 發布時伺服器本來就會檢查，未通過時發布失敗並顯示為「未通過」（同現況）。

#### 按鈕

| 狀態                | 按鈕（左到右）                                                            | 對應 API（不變）                                                                     |
| ------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 草稿                | `捨棄草稿`（ghost）、`儲存`、`預約…`、`立即發布`（主要）                  | 儲存＝`KEEP_STATUS`；立即發布＝先儲存再 `IMMEDIATE`；捨棄＝`DELETE .../draft`        |
| 草稿，按了「預約…」 | `捨棄草稿`、`儲存`、[日期][時間] `取消`、`預約發布`（主要）               | 先儲存再 `SCHEDULED`                                                                 |
| 已排程              | `取消排程`（ghost）、[日期][時間]、`儲存`、`立即發布`、`更新預約`（主要） | 取消排程＝`DRAFT`；儲存＝`KEEP_STATUS`；立即發布＝`IMMEDIATE`；更新預約＝`SCHEDULED` |

- 「至少 1 分鐘後、最多 90 天內」只在預約時間錯誤時顯示（取代常駐提示）。
- 「預約…」的日期時間預設值同現況（下一個整點）；已排程時帶入目前預約時間。
- 已排程時不顯示「捨棄草稿」（取代原本的停用按鈕）。
- 移除：標題列的「評測」按鈕、已排程黃色說明橫幅（排程時間顯示於標題狀態標籤）、「發布方式」單選鈕。

### 3.2 沒有編輯中版本

- 唯讀顯示目前生效的內容（`SafeMarkdown`）。
- 動作列：提示「編輯會建立一份草稿，發布前不影響線上。」＋`複製 Markdown`＋`編輯`（主要；即原本的「建立草稿」，`POST .../draft`）。
- 動作列與編輯時相同（sticky）：內容超過螢幕高度時固定在畫面下方；內容不另設捲動框，隨頁面捲動。
- 移除：唯讀橫幅、「狀態／原作者／發布／預約時間／套用來源」資訊卡、重複的「建立草稿」按鈕。

### 3.3 沒有編輯權限

欄位唯讀、不顯示動作列（同現況）。

## 4. 版本分頁

```
┌ 版本列表（280px）─────────┬ 右側 ─────────────────────────────────┐
│ ☑ 草稿         10/27 16:02│ − 目前生效 10/24 19:31  ＋ 草稿 10/27 16:02 │
│   it.admin・實測：第二輪… │ 名稱相同                        ＋7 −2 行 │
│ ☑ 目前生效     10/24 19:31│ … 行內標示的差異 …                      │
│   system・[讚]4・[倒讚]1   │                                         │
│ ☐ 已封存       10/20 10:00│                                         │
│ 顯示已捨棄（1） [比較勾選的兩版]                                     │
└───────────────────────────┴─────────────────────────────────────────┘
```

### 4.1 版本列表

- 每列兩行：狀態＋時間；操作者・修改說明（截斷）。已發布、已封存列另顯示讚／倒讚（格式同現況），列表底部保留 180 天小字。
- 「以…的版本為底」「原作者」「原預約」移到右側 meta。
- 已捨棄預設隱藏，底部「顯示已捨棄（N）」切換（同現況）。
- 每列有勾選框；底部常駐 `比較勾選的兩版`：沒有剛好勾兩列時為停用外觀（`aria-disabled="true"`，不用原生 `disabled`，才能收到 hover），按下無作用；滑鼠移上或鍵盤聚焦時在按鈕旁顯示提示「勾選任兩個版本後比較」（`role="tooltip"`，以 `aria-describedby` 連到按鈕）。移除常駐的「勾選任兩個版本後比較」提示文字。
- 列上**沒有**「套用」按鈕。
- 畫面以時間辨識版本，不顯示版本號（同現況）。

### 4.2 進入分頁時的預設

| 情況                         | 右側                                     | 勾選         |
| ---------------------------- | ---------------------------------------- | ------------ |
| 有編輯中版本，也有已發布版本 | 「目前生效 vs 草稿（或已排程）」差異     | 預先勾這兩列 |
| 只有已發布版本               | 目前生效版本的唯讀內容                   | 無           |
| 只有編輯中版本（從未發布）   | 提示「尚未發布過，草稿請在內容分頁編輯」 | 無           |

### 4.3 點選版本列

- 草稿或已排程列 → 切到「內容」分頁。
- 其他狀態 → 右側唯讀檢視：
    - meta 一行：{狀態}・{時間} {操作者} {發布／捨棄}・{修改說明}・以 {時間} 的版本為底・原預約 {時間}・已被 {時間} 的版本取代（各項沒有值就省略）。
    - 內容（`SafeMarkdown`）。
    - 動作列：`複製 Markdown`＋`以此版本建立草稿`（主要；無編輯權限時不顯示）。已發布、已封存、已捨棄皆可（同現況的 `APPLICABLE`），「目前生效」列用同一個按鈕與文案。動作列同 3.2（sticky，固定在畫面下方）。

### 4.4 以此版本建立草稿（原「套用」）

- API 與兩段式確認不變（`AI_CONFIG_OVERWRITE_PENDING` → 確認 → 再呼叫）。
- 確認框精簡為標題＋一句話，移除「來源／目前草稿／套用後」摘要表：
    - 標題：「以 {來源時間} 的版本建立草稿？」
    - 有草稿：「目前 {草稿時間} 儲存的草稿會改為已捨棄，可在版本列表找回。」
    - 已排程：「目前預約於 {預約時間} 發布的版本會取消排程並改為已捨棄，可在版本列表找回。」
    - 按鈕：`取消`、`建立草稿`。
- 有未儲存的修改時先問「放棄尚未儲存的修改？」（同現況）。
- 完成後切到「內容」分頁。

### 4.5 比較

- 標題列：「− {較舊版本狀態} {時間}」「＋ {較新版本狀態} {時間}」「＋{n} −{m} 行」。較舊在 −、較新在 ＋（同現況）。
- 名稱沒有差異：不顯示名稱區塊，改為一行小字「名稱相同」。
- 內容：逐行差異（同現況）；**成對的刪除／新增行**另以行內標示標出實際改動的字（比對頭尾相同字元，中間不同的部分標色）。
- 移除底部「要改用某個版本的內容，請在版本歷程對它按「套用」」。
- 差異過大（`DiffTooLargeError`）處理同現況。

## 5. 評測分頁

### 5.1 結論卡（分頁最上方，依狀態擇一）

| 狀態             | 標題與副標                                                                                                                                                                                                           | 按鈕                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 已評測           | 依 5.2：「▲ 草稿比目前生效的版本好」／「▼ 草稿有指標變差」／「≈ 草稿和目前生效的版本差不多」；副標列出有變化的品質指標（例「正確率 65% → 82%」），其他寫「其他指標持平」，Token 有變化時加「平均 Token 多／少 {n}%」 | `重新評測`                             |
| 評測後又改過內容 | 「評測後內容已修改，結果可能不準」，下方仍列出原結果                                                                                                                                                                 | `重新評測`                             |
| 尚未評測         | 「這份草稿還沒評測」；「會用 {N} 題分別問目前生效的版本和草稿，比較兩者的回答，約需 2–3 分鐘。」                                                                                                                     | `執行評測`                             |
| 執行中           | 「評測中 {完成}/{總數}」＋進度條；已完成題目即時出現在下方（同現況）                                                                                                                                                 | —                                      |
| 有未儲存的修改   | 「有未儲存的修改，評測只會用已儲存的內容」                                                                                                                                                                           | `儲存並評測`（先儲存，成功後開始評測） |
| 他人評測中       | 「{觸發者} 正在評測「{名稱}」（{完成}/{總數}），完成後才能執行」                                                                                                                                                     | —                                      |
| 沒有編輯中版本   | 有歷史結果時照常顯示；副標「評測會比較草稿和目前生效的版本，請先在內容分頁按「編輯」」                                                                                                                               | —                                      |
| 已完成但沒有可比較的摘要 | 「這次評測沒有可比較的結果」（`COMPLETED` 的結果沒有 `summary`；實作時補上，只在有編輯中版本、已儲存、且已評測時出現）                                                                                  | `重新評測`                             |

- 沒有 `AI_CONFIG_EDIT`：不顯示任何按鈕，結果照常可看（同現況）。
- 評測失敗（`FAILED`）：「這次評測沒有完成，已完成的題目仍列在下方」（同現況文字）＋`重新評測`。只在失敗的那次評測的 `candidateVersion`、`candidateDocVersion` 與目前編輯中版本相同時顯示；評測的是較舊的儲存內容時，改依上表的尚未評測／評測後已修改／已評測規則顯示。

### 5.2 結論規則（`overallVerdict(summary)`）

品質指標：正確率、工具選擇正確率、分類正確率、應拒答題的拒答率、一般題的拒答率。各指標的變好／變差／持平沿用現有 `rateDirection()`（差 1 題以內為持平；一般題拒答率越低越好）。

1. 任一品質指標變差 → **▼ 有指標變差**
2. 否則任一品質指標變好 → **▲ 變好**
3. 否則 → **≈ 差不多**

Token 不影響結論，只寫在副標。

### 5.3 全部指標（預設收合）

- 「全部指標 ▸」展開後為表格：指標、目前生效、草稿、變化。
- 變化欄用文字：「變好」「變差」「持平」，後接括號內的題數差（草稿減目前生效，例：「變好（+3 題）」；一般題拒答率增加為「變差（+2 題）」）；分母 0 為「—」。Token 列為「多 {n}%」（變差，紅色）／「少 {n}%」（變好）／「持平」。
- 「一般題的拒答率」「平均 Token」名稱旁小字「越低越好」。
- 表格下一行：「差 1 題以內標為持平，可能只是模型隨機性。」

### 5.4 結果不同的題目

- 標題「結果不同的題目 {n} 題」；下方「顯示全部 {N} 題」／「只看結果不同的」連結切換（取代勾選框；預設只看不同的，同現況）。
- 每列：**題目內容**、小字分組、狀態標籤（變好／變差／執行中）。
- 展開：題目代號（例 `Q5-opening`）以小字顯示於展開區頂端；兩欄標題為「目前生效」「草稿」。每欄：
    - 回答（`SafeMarkdown`）或作答失敗訊息（同現況）。
    - 分類不符時一行「分類不符：預期 {分類}，實際 {分類或「無」}」，路由失敗（`FALLBACK`）時實際為「無（路由失敗，已載入全部）」；分類正確時不顯示路由。
    - 沒通過的原因逐條列出（工具、缺少／不該出現的字詞、數字、拒答、評審未達成的要點）；全部通過時顯示「全部通過」。該欄作答失敗（顯示錯誤訊息）時不顯示「全部通過」。
    - 移除「工具 ✓ 字詞 ✓ 數字 ✓」與「評審：無」。

### 5.5 底部連結

- 「評測歷程（{n}）」：展開列出歷程（同現況），點選看舊結果時結論卡上方顯示「正在看 {時間} 的結果・回到最新」。
- 「題庫（{N} 題）」：開啟現有題目對話框；只調整欄寬，讓「應拒答」「預期分類」欄位標題不被擠成直排。

## 6. 發布前驗證規則

適用所有執行驗證的地方（同現況）：`POST .../draft/validate`、發布、已排程版本的儲存、排程到期發布、開始評測、seed 驗證測試。

| 規則                                                         | 現況                                                                                                                         | 調整後                                                                                             |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `NOT_EMPTY`、`MAX_SIZE`                                      | —                                                                                                                            | 不變                                                                                               |
| `REQUIRED_SECTION`                                           | System Prompt：`## 角色`、`## 安全規則`、`## 回答格式`；問題分類：`## 適用問題`、`## 回答套版`、`## 範例問題`、`## 注意事項` | System Prompt：無。問題分類：只有 `## 適用問題`，且章節內容不可空白                                |
| `EXAMPLE_QUESTIONS`                                          | 問題分類必須有 1–5 題，每題最多 40 字                                                                                        | 0–5 題，`## 範例問題` 章節可省略；每題最多 40 字                                                   |
| 禁止內容：越權指令                                           | 擋「忽略以上規則」「ignore previous instructions」等                                                                         | 移除                                                                                               |
| 禁止內容：網址                                               | 任何 `http://`、`https://`                                                                                                   | 只擋 host 不在白名單的網址（6.1）                                                                  |
| 禁止內容：IP                                                 | 與網址同一項                                                                                                                 | 獨立一項，一律擋，不受白名單影響（`http://10.1.2.3` 也擋）                                         |
| 禁止內容：API key、密碼、身分證號、手機、顧客編號            | —                                                                                                                            | 不變                                                                                               |

- 「章節內容不可空白」：`## 適用問題` 到下一個 `## ` 標題之間至少有一行非空白文字（與 `InstructionRouter` 取 scope 的範圍相同）。理由：路由只看分類名稱與這一節，空白時路由只能靠名稱判斷。
- 錯誤訊息（`rule` 不變）：
    - 缺少：`缺少必要章節「## 適用問題」`（同現況格式）
    - 空白：`「## 適用問題」不可空白`
    - 範例過多：`「範例問題」最多 5 題，目前有 {n} 題`；過長：`「範例問題」每題最多 40 字`（同現況）
    - 網址：`第 {n} 行疑似包含未允許的網址，請移除`；IP：`第 {n} 行疑似包含 IP 位址，請移除`
    - 實作的 IP 訊息為 `第 {n} 行疑似包含IP 位址，請移除`（「包含」與「IP」之間沒有空格）：訊息由「第 {n} 行疑似包含」＋類型名稱＋「，請移除」串接，與既有的 `API key 或 token` 相同格式，文件與測試以實際文字為準
- 規則只有 `## 適用問題` 不可空白是變嚴；7 份 seed 都有內容。

### 6.1 網址白名單

```yaml
ai-assistant:
    config:
        allowed-url-hosts: [] # prompt 內允許出現的網址 host；空白＝不允許任何網址（等同現況）
```

- `AiAssistantProperties.Config` 新增 `List<String> allowedUrlHosts`；未設定視為空清單。
- 比對：取 `http://` 或 `https://` 之後連續的主機名稱字元（英數字、`.`、`-`）當 host，遇到其他字元即停止，所以 Markdown 連結的 `)`、中文標點（如 `。`）等緊接在後的字元不算進 host；host 結尾的 `.` 忽略。轉小寫後與清單**完全相等**才放行（不含子網域；`docs.example.com` 要另外列）。host 後面緊接 `@`（如 `https://docs.example.com@evil.com`）一律視為不允許。
- 不與 `market.twse.allowed-hosts` 共用：那份管的是後端程式可以連線的對象；這份管的是 prompt 裡可以寫、模型可能照抄給使用者的連結，用途與審核對象不同。
- 修改清單需改設定並重新啟動（POC 不提供管理畫面）。

### 6.2 安全規則

System Prompt 不再要求 `## 安全規則`。平台安全規則由 `SafetyRules` 固定接在每次 prompt 的最後（`PromptAssembler`），管理者無法修改或移除。管理者在 System Prompt 另寫的安全要求照常生效，但不檢查。

## 7. 快捷問題

- `SuggestionService` 略過沒有範例問題的分類，`/suggestions` 回應不含它。
- `QuickQuestions.vue` 也不顯示 `questions` 為空的分類；全部為空時整塊不顯示（同沒有分類）。分類色塊依過濾後的順序編號。
- 管理頁預覽：問題分類沒有範例問題時，「快捷按鈕預覽」顯示「沒有範例問題，對話視窗不會顯示這個分類」。
- 路由不受影響：沒有範例問題的分類照常參與路由（路由只看名稱與 `## 適用問題`）。

## 10. 測試與驗收

### 10.1 前端單元測試（vitest）

- `overallVerdict()`：任一品質指標變差 → 變差（即使另一項變好）；只有變好 → 變好；全部持平 → 差不多；只有 Token 變化 → 差不多。
- `lineDiff` 行內片段：中間改字、頭尾新增、完全不同、空行。
- `PublishBar`：草稿與已排程各按鈕送出的事件（取消排程 → `DRAFT`；已排程的立即發布 → `IMMEDIATE`）；已排程不顯示「捨棄草稿」；預約時間錯誤才顯示範圍提示。
- `PromptManagementPage`：換設定回到內容分頁；切分頁保留未儲存修改；版本分頁預設（4.2 三種情況）；點草稿列切到內容；以舊版本建立草稿後切到內容；分頁結論符號只在「已評測且未修改」時出現。
- `EvaluationView`：「儲存並評測」先儲存再開始；儲存失敗不開始；各狀態的結論卡。
- `EvaluationCaseList`：題目內容優先；未通過原因清單；全部通過文字；分類不符才顯示路由。
- `usePromptAdmin`：載入有草稿的設定後自動檢查；儲存成功後再檢查一次；換設定後才抵達的舊回應被丟棄；檢查中不影響 `busy`。
- `ValidationPanel`：檢查中、通過、未通過、有未儲存修改四種顯示；沒有按鈕。
- `MarkdownEditor`：問題分類缺 `## 適用問題` 才顯示「缺少」；System Prompt 不顯示。
- `QuickQuestions`：0 題的分類不顯示；全部 0 題時整塊不顯示。
- `ConfigPicker`：兩個分組與狀態標籤；搜尋名稱與 key、整組隱藏、無結果文字；鍵盤展開、↑↓、Enter 選取、Esc 關閉並還焦點；點外面關閉；選取時 emit，由頁面走換設定流程（取消後維持原設定）。
- 版本分頁比較按鈕：未勾滿兩列時 `aria-disabled` 且按下不比較；提示文字以 `aria-describedby` 連到按鈕；勾滿兩列時可比較。
- 更新現有測試中斷言已移除文字的部分（「返回編輯」「存成草稿」「重新檢查」「尚未檢查」「工具 ✓」「勾選任兩個版本後比較」「越權指令」等）。

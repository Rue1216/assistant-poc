## 決策歷程

### 問題分類：全部載入 → 先路由（2026-10-27）

| 日期 | 做法 | 原因 |
|---|---|---|
| 2026-10-19（commit `1e2717d`，移除 `relatedTools` 後） | 每次提問把**全部**已發布的問題分類放進 system message，由回答模型自己判斷屬於哪一類 | 最簡單，不需要額外的模型呼叫；POC 只有 5 個分類，約 3,600 字 |
| 2026-10-27 | **先路由**：多一次模型呼叫選出分類，回答時只載入該分類；快捷按鈕帶 `categoryKey` 略過路由；路由失敗退回載入全部 | 見下 |

改為先路由的原因：

1. **回饋歸屬**：全部載入時，一則回答的 👍／👎 只能算進所有已發布的分類，版本歷程的統計看不出是哪一個分類的品質。先路由後，回答實際使用的分類（`routeSource`、`instructionKey`）記在稽核裡，統計只計入確定使用該分類的回答。
2. **token 隨分類數成長**：分類內容占 system message 的一半，每個模型回合都重送，分類越多成本越高，模型選錯分類的機會也越多。先路由後，每題只送一個分類，代價是一次小型的路由呼叫。
3. **可評測**：分類是否選對可以進評測集（`expect.category`、分類正確率），修改「## 適用問題」時能看出路由變好或變差。

取捨：每題多一次模型呼叫（延遲與少量 token）；路由失敗時退回全部載入，回答不受影響。設計見 [instruction-routing-design](superpowers/specs/2026-10-27-instruction-routing-design.md)。仍不做：一題載入多個分類、向量或關鍵字取代模型路由、路由使用較小的模型（保留設定擴充空間）。
